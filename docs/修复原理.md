# 修复原理与补丁细节

本文档说明 PCL 2.99.0.0 (413) 中被替换的两处逻辑，以及本项目恢复它们的精确方式，
本文档与补丁脚本由 **DeepSeek** 分析生成。

方便审计与复现（`patcher/apply_patch.ps1` 就是按本文档实现的）。

## 分析环境

- 目标：官方 PCL 2.99.0.0 (413)，.NET Framework 单文件 WPF 程序（PE32，未混淆，类型/方法名完整）
- 工具：ILSpy（反编译）、Mono.Cecil（读取/重写 IL）
- 原始文件 SHA256：`6B6E1260CB5A1D6A303855F1C60CAB3D0BC1AEBBA7E40A964180188B271E7386`

替换后会出现字符串：

```
为遵守相关法律法规，PCL 暂时不再提供 MC 下载功能，非常抱歉 qwq……
```

反编译后可以直接看到该字符串被用于两处 `throw new Exception(...)`。

## 补丁 1：恢复「下载 → 原版游戏」

方法：`PCL.PageDownloadInstall::LoaderInit()`

原版 2.99.0.0 中，该方法里的 `PageLoaderInit` 调用第 5 个参数（版本列表加载器）被替换为：

```csharp
new ModLoader.LoaderTask<string, ModDownload.DlClientListResult>("关闭下载", a0 => {
    throw new Exception("为遵守相关法律法规，PCL 暂时不再提供 MC 下载功能，非常抱歉 qwq……");
})
```

而正常实现应传入静态字段：

```csharp
ModDownload.DlClientListLoader
```

对应 IL（方法体 IL 的文件偏移 `0x2C0C0`，从 `0x2C0DA` 起 48 字节）原为：

```
72 33 47 01 70        ldstr "关闭下载"
7E FB 09 00 04        ldsfld _Closure$__::$IR3-3
2C 07                 brfalse.s
7E FB 09 00 04        ldsfld _Closure$__::$IR3-3
2B 16                 br.s
7E F9 09 00 04        ldsfld _Closure$__::$I
FE 06 67 14 00 06     ldftn _Lambda$__R3-3
73 8D 05 00 0A        newobj Action`1<LoaderTask<...>>::.ctor
25                    dup
80 FB 09 00 04        stsfld _Closure$__::$IR3-3
14                    ldnull
18                    ldc.i4.2
73 8E 05 00 0A        newobj LoaderTask<...>::.ctor
```

替换为等长的：

```
7E 0F 04 00 04        ldsfld PCL.ModDownload::DlClientListLoader
00 × 43               nop × 43（填充）
```

该字段类型 `LoaderTask<string, DlClientListResult>` 与 `PageLoaderInit` 泛型参数一致，
因此原版 2.13.1.1 (408) 就是这样调用的；恢复后下载页正常加载版本列表。

## 补丁 2：恢复 `ModModpack.ModpackInstall(string, string, string)`

原版方法在识别完整合包类型（局部变量 `num`）后，应执行如下逻辑：

```csharp
switch (num) {
    case 0: return InstallPackCurseForge(File, zipArchive, archiveBaseFolder, InstanceName, Logo);
    case 1: return InstallPackHMCL(File, zipArchive, archiveBaseFolder);
    case 2: return InstallPackMMC(File, zipArchive, archiveBaseFolder);
    case 3: return InstallPackMCBBS(File, zipArchive, archiveBaseFolder, InstanceName);
    case 4: return InstallPackModrinth(File, zipArchive, archiveBaseFolder, InstanceName, Logo);
    case 9: return InstallPackLauncherPack(File, zipArchive, archiveBaseFolder);
    default: return InstallPackCompress(File, zipArchive);
}
```

2.99.0.0 把它替换成了：

```csharp
throw new Exception("为遵守相关法律法规，……");
```

补丁脚本使用 Mono.Cecil 在原位置重建 IL：

- 先判断 `num >= 0`（负数走 default），再 `switch`；
- 每个分支写出与官方旧版一致的 `Logger.Info("整合包种类：……")` 日志；
- 调用仍然存在的 `InstallPack*` 方法；
- 由于外层有 `finally { zipArchive?.Dispose(); }`，返回值先存入新增局部变量，用 `leave` 跳出 try，再 `ret`。

## 补丁 3：恢复 `ModModpack.ModpackInstall()`（安装已有整合包）

原版为：

```csharp
string text = Dialogs.SelectFile("选择整合包压缩文件", false, null,
    /* 筛选：整合包文件(*.rar;*.zip;*.mrpack) */).FirstOrDefault();
if (string.IsNullOrEmpty(text)) return;
ModBase.RunInThread(() => { try { ModpackInstall(text); } catch (Exception ex) { ... } });
```

2.99.0.0 的方法体被替换为只弹一行提示。补丁脚本重建 IL：
读取文件选择框结果、空值判断、创建闭包 `_Closure$__0-0`、写入捕获字段、
以 `Action` 交给 `ModBase.RunInThread` 在后台调用 3 参数重载。

## 已知注意事项

- 修改后的 exe 不再具有官方数字签名，可能被 SmartScreen 或杀毒软件误报（属常见现象）。
- 程序版本号未修改，仍显示 2.99.0.0 (413)；PCL 的公告/更新检查逻辑未改动。
- 本项目仅恢复下载与整合包安装入口，不涉及其他任何功能。
